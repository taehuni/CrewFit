# CrewFit 서비스 흐름·동의 구조 검토

검토일: 2026-11-21 · 대상: 현재 작업트리(미커밋 변경 포함) · 성격: 코드 기반 서비스 설계 감사

## 1. 결론과 범위

가입 시 기본 이용약관과 개인정보 처리 안내를 제공하고, 필요한 동의를 구분하여 받는 것이 적절하다. 설치형 앱이라고 카메라·위치·외부 AI 분석까지 가입 필수로 묶지는 않는다. 실제 사용할 때 목적을 설명하고 선택하게 하며, 유효한 선택은 계정에 저장해 반복 질문을 줄인다. 기기의 카메라·위치 권한은 계정 동의와 별개다. 영상 녹화, 개인 보관, 오류 검토용 공유 역시 서로 다른 행동이다. 현재 가장 큰 공백은 가입 공통 안내, 일반 AI 코칭의 외부 데이터 처리 설명·선택, 탈퇴·삭제 경로다. 사진 분석의 목적별 선택과 녹화·보관 분리는 유지할 가치가 있다.

대상 사용자는 운동을 처음 시작하는 사람부터 기록·크루·식단을 함께 이용하는 일반 회원이다. 평가 기준은 첫 사용 이해도, 반복 사용 부담, 선택권, 실패 후 복귀, 개인정보 통제, 플랫폼별 동작 차이다. 사용자 요청에 따라 공개 MIT 라이선스의 [UX Audit 스킬](https://github.com/paulunemoon/ux-audit-skill)을 설치하고, 온보딩·작업 흐름·신뢰·플랫폼 기준을 적용했다. 가입·동의와 전체 서비스 흐름을 두 담당자가 별도로 읽기 전용 검토했고 메인에서 통합했다.

| 알림·마케팅 | 일정 알림 등 해당 기능을 켤 때 OS 권한. 홍보 수신은 별도 선택 | 서비스 알림과 마케팅을 한 항목으로 묶지 않음. OS 허용만으로 홍보 수신 동의로 간주하지 않음 |

Android와 Apple의 공식 지침도 기능을 사용하는 맥락에서 필요한 권한을 요청하는 방향이다. 다만 iOS의 시스템 권한 사전 설명 화면은 별도 설계 제약이 있으므로 Android의 두 버튼 권한 안내를 그대로 복제하지 않는다. 서비스 자체의 법적 동의 선택 화면과 OS 허용 창을 구분한다. [Android 권한 지침](https://developer.android.com/training/permissions/requesting), [Apple 개인정보·권한 지침](https://developer.apple.com/design/human-interface-guidelines/privacy/)

## 3. 동의 버튼을 줄여도 되는 범위

‘명시적인 선택’과 ‘매번 같은 동의 버튼’은 다르다. 최초 필요한 선택은 남기되, 이후에는 상태와 변경 경로로 대체한다. 자동 체크, 기존 동의 없는 회원을 동의한 것으로 간주, 카메라 허용을 외부 사진 전송 허용으로 간주하는 방식은 사용하지 않는다.

가입에는 기본 약관 확인과 개인정보 안내를 둔다. 필요한 개별 동의가 있다면 목적별로 나누고 선택 항목을 거절해도 가능한 핵심 기능을 유지한다. 기능 첫 사용에는 짧은 요약과 상세 내용을 함께 제공하고 ‘동의하고 시작’ 같은 명시적인 행동을 사용한다. 재사용에는 ‘AI 사진 분석 켜짐 · 설정’처럼 줄인다. 목적·받는 곳·보관 등 선택에 중요한 내용이 바뀌면 변경 내용을 설명하고 필요한 새 동의를 받는다.

법적으로 모든 개인정보 처리에 체크박스가 필요한 것은 아니다. 계약 이행에 필요한 처리 등 동의 외 근거도 있고, 동의를 이용할 때에는 목적·항목·보유 기간·거절의 효과를 알려야 한다. 따라서 ‘개인정보 처리방침 전체 동의’ 하나로 처리 근거를 대신하지 않는다. [개인정보 보호법 제15조](https://law.go.kr/lsLinkCommonInfo.do?chrClsCd=010202&lsJoLnkSeq=1022694549)

건강정보에 해당하는 인바디·알레르기 등의 처리는 다른 개인정보와 별도 동의 또는 법령상 근거 검토가 필요하다. 사진이라는 이유만으로 모든 사진을 생체인식정보라고 단정하지는 않는다. 국외 이전도 별도 동의 외에 계약상 필요한 위탁·보관 등 법정 요건에 따른 다른 근거가 있을 수 있으므로, 실제 제공자 계약과 처리 구조를 먼저 확인해야 한다. 동의를 근거로 삼는다면 이전 국가·수신자·목적·기간 등을 구체화해야 한다. [제23조](https://www.law.go.kr/lsLinkCommonInfo.do?chrClsCd=010202&lsJoLnkSeq=1029335227), [제28조의8](https://www.law.go.kr/LSW/lsLinkCommonInfo.do?chrClsCd=010202&lsJoLnkSeq=1034513289)

## 4. 현재 발견한 문제

우선순위 P1은 다음 기능 확대 전에 처리할 흐름, P2는 이어서 개선할 사용성이다. 심각도는 사용자 영향 기준이며 법 위반 확정 판정이 아니다. 현재 증거만으로 Blocker/P0은 지정하지 않았다. 공수 S/M/L은 상대적인 구현 범위이며 일정 약속이 아니다.

### ONB-01 · 가입 방식별 공통 안내·버전 확인 부재

- **분류 / 심각도 / 근거:** 온보딩·신뢰 / High·P1 / 코드 확인.
- **위치:** [SignupPage.jsx:53](../client/src/features/auth/SignupPage.jsx#L53), [authLinks.js:21](../client/src/features/auth/authLinks.js#L21), [CompleteProfile.jsx:13](../client/src/features/auth/CompleteProfile.jsx#L13), [RequireAuth.jsx:21](../client/src/features/auth/RequireAuth.jsx#L21).
- **증거:** 가입 폼은 이름·닉네임·이메일·비밀번호, Google 마무리는 이름·닉네임이다. 공통 정책 확인·버전 기록이 없고 진입 검사는 Google 프로필 완성 중심이다.
- **사용자 영향:** CrewFit 자체 조건과 데이터 이용 범위를 확인할 공통 단계가 없다. 이메일 화면에만 체크박스를 추가하면 Google·기존 회원·직접 주소 진입이 빠진다.
- **권고 / 공수:** 정책 문서와 처리 근거를 먼저 정리한 뒤 가입 방식과 무관한 계정별 확인 구조 적용. 기존 회원은 미확인/필요한 변경만 안내하고 본인 데이터 열람·삭제 요청 경로까지 막지 않는다. **L**.

### TRUST-01 · 일반 코칭의 외부 처리 설명·선택이 사진 분석보다 약함

- **분류 / 심각도 / 근거:** 신뢰·데이터 사용 / High·P1 / 코드 확인, 이해도 영향은 추론.
- **위치:** [CoachPage.jsx:151](../client/src/features/coach/CoachPage.jsx#L151), [coach.js:54](../server/services/coach.js#L54), [coach.js:19](../server/services/coach.js#L19), [NutritionCoach.jsx:23](../client/src/features/coach/NutritionCoach.jsx#L23), [feedback.js:141](../server/services/feedback.js#L141).
- **증거:** 코칭은 최근 운동·식단 메모·목표·선호·알레르기·대화를 구성하여 외부 AI에 전달한다. 참고 기록 설명은 빈 대화에만 표시되고 사진 분석과 같은 계정별 처리 설정은 없다. ‘AI가 참고’라는 기존 안내는 있으므로 완전한 무고지로 단정하지 않는다.
- **사용자 영향:** 이미 대화가 있는 회원은 어떤 기록이 전달되는지 다시 확인하기 어렵다. ‘본인만 볼 수 있음’은 다른 회원에게 비공개라는 의미와 외부 처리 의미를 혼동시킬 수 있다.
- **권고 / 공수:** 첫 AI 사용의 공통 안내와 상시 설정 경로, 건강정보 처리 범위 분리, 서버 전송 직전 검증. 직접 입력한 메시지에도 건강정보가 들어갈 수 있으므로 자동 첨부 설정만으로 충분하다고 보지 않는다. **L**.

### TRUST-02 · 철회·개별 삭제·회원 탈퇴를 연결하는 경로 부재

- **분류 / 심각도 / 근거:** 데이터 통제 / High·P1 / 코드 검색 범위 내 확인.
- **위치:** [PosePrivacySettings.jsx:10](../client/src/features/pose/PosePrivacySettings.jsx#L10), [ProfileEditor.jsx:50](../client/src/features/profile/ProfileEditor.jsx#L50), [me.js:7](../server/routes/me.js#L7), [poseVideos.js:24](../server/services/poseVideos.js#L24).
- **증거:** 사진 분석 중지와 본인 영상 재생·삭제는 있다. 계정 설정과 관련 서버 경로에서 회원 탈퇴·전체 데이터 삭제 요청 흐름은 찾지 못했다. 이는 기존 기능 실패가 아니라 미구현 흐름이다.
- **사용자 영향:** 분석 중지와 영상 삭제는 각각 가능하지만, 계정 설정에서 이를 함께 확인하거나 회원 탈퇴·전체 데이터 삭제를 요청할 경로는 없다.
- **권고 / 공수:** 설정 안의 개인정보·연결 관리와 계정 삭제 경로. 크루장 양도, 공개 글/댓글, 보관 의무, 외부 캘린더 일정의 처리 결과를 삭제 전에 설명. **L**. Google Play 공개 배포 시 앱 안과 앱 밖의 계정 삭제 요청 경로도 준비해야 한다. [Google Play 계정 삭제 요구사항](https://support.google.com/googleplay/android-developer/answer/13327111?hl=en-en)

### PLAT-01 · Android GPS 지속 측정 설명이 시작 후에 있음

## 5. 시각 구성 제안

다음은 실제 화면에서 새로 발견한 깨짐 목록이 아니라, 확인된 흐름을 개선하기 위한 디자인 제안이다.

- **가입:** 기존 로고·색상·둥근 폼을 유지한다. 입력 아래 필수 확인 영역 하나와 정책 링크를 두고 기능별 카메라/GPS/AI 설정을 쌓지 않는다. 필요 없는 전체 동의 버튼은 넣지 않는다.
- **자세 측정 첫 사용:** 운동 준비와 카메라가 중심이다. 분석 목적·보내는 정보·선택을 한 구역에 모으고 세부 내용은 읽을 수 있는 별도 화면/상세 링크로 제공한다. 필수 고지 내용을 작은 회색 글자에만 숨기지 않는다.
- **재사용:** 긴 설명 카드 대신 ‘자동 판별 켜짐’, ‘측정 중 AI 관찰 켜짐’과 설정 진입. 녹화는 작은 독립 선택, 시작은 명확한 주 버튼 하나로 둔다.
- **모바일:** 짧은 선택은 하단 시트, 길고 중요한 정책은 읽을 수 있는 화면으로 분리한다. 닫기/뒤로가기·거절 경로를 확보하며 키보드·안전 영역 때문에 확인 버튼이 가려지지 않게 한다.
- **PC:** 휴대폰용 전체 화면 동의 창을 크게 늘리지 않는다. 본문 너비와 나란한 설명 구역을 사용하고 키보드 포커스와 닫은 후 복귀 위치를 유지한다.
- **설정:** 개인정보·AI 사용 / 연결 서비스 / 내 데이터 관리로 정리하되 별도 하단 탭을 늘리지 않는다. ‘사용 중지’, ‘영상 삭제’, ‘탈퇴’를 각각 다른 결과로 설명한다.

| 6 | 코칭 초안·식단 복귀·캘린더 계정 연결 개선 | 중단→복귀 후 원 작업 보존, 중복 저장/타 계정 혼합 없음 |
| 7 | PC 웹·모바일 웹앱·Android 앱 검수 | 각 환경 실제 결과와 미확인을 별도 기록. 미확인 결과를 통과로 바꾸지 않음 |

공통 저장 설계에서는 계정·목적·고지 버전·선택/철회 시각을 기록한다. 현재 pose 구현은 버전별 상태를 저장하지만 같은 버전 재승인 시 과거 철회 시각을 덮어쓸 수 있으므로, 변경 이력 보존 방식은 운영 필요와 최소 보관 원칙을 정한 뒤 보강한다. 불필요한 기기 식별자·IP를 동의 증빙 명목으로 새로 수집하지 않는다.

## 8. 유지할 설계와 남은 결정

유지할 것: 목적별 사진 분석 선택과 서버의 전송 전 검사, 녹화와 영상 보관의 분리, 결과 저장과 Google 일정 전송의 분리, PC GPS의 기기 기준 QR 안내, 인식 실패 시 직접 기록 대안. 실제 적용·저장은 운영 설정 확인 전까지 완료로 주장하지 않는다.

영상은 요청자 소유 측정을 확인한 뒤 짧은 유효 기간의 링크를 발급하는 구조다. ‘앱에서 본인만 조회’와 ‘운영자도 기술적으로 절대 접근 불가’는 다르다. 개발자 검토용 별도 공유 흐름은 현재 확인되지 않았다. 자동 삭제는 사용자의 최신 요청대로 도입하지 않은 상태를 전제로 평가했다.

남은 결정은 운영 주체·연락처, 대상 연령, 실제 제공자별 국가·계약·보관 설정, 공개 출시 전 영상 보관 정책, 개발자 검토 접근 범위, 실명 필요성이다. 이 정보 없이 법적 문구를 확정하거나 ‘모든 동의를 없애도 된다’고 결론 내리지 않는다. 이번 권고는 **기본 가입 안내 + 기능 첫 사용 선택 + 계정에 기억 + 언제든 변경 + 별도 저장/공유 확인**이다.

## 9. Product Design 연결 후 실제 화면 추가 검토

같은 날 Product Design의 화면 캡처 기반 감사 절차를 적용했다. 아래 근거는 모두 이번 후속 검토에서 새로 캡처·저장·열람한 화면이다. 기존 코드 감사와 분리하며, 새 계정 가입·동의 승인·카메라 촬영·분석·저장까지 완료한 결과가 아니다.

### 환경과 단계

- 주소: `http://localhost:5173`, 현재 로컬 작업트리. 배포판 또는 배포 커밋으로 간주하지 않는다.
- 기본 화면: PC IAB 1264×712. 추가 화면: 동일 PC 브라우저를 390×844로 변경. 기기/브라우저 엔진을 iPhone으로 바꾼 테스트가 아니다. 확인 후 임시 화면 크기를 원상 복구했다.
- 시작 상태: 기존 로그인 유지로 `/login`에서 `/home`으로 이동. 신규 가입 화면을 보려고 로그아웃하거나 계정을 새로 만들지 않았다.
- 실제 iPhone·Android Chrome·설치형 Android 앱은 이번 후속 화면 검토에서도 미확인이다. 브라우저/앱 버전, 권한 창, 카메라 및 OAuth 왕복은 별도 실기기 검증이 필요하다.

| 단계 | 실제로 확인한 동작 | 상태 |
|---|---|---|
| 1 | 코칭 메뉴 진입, 맞춤 계획·리포트·대화 구분 | 진입 정상. 다른 목적의 카드 구분은 명확 |
| 2 | 운동 자세 확인 진입, 시작 안내와 카메라 켜기 위치 | 진입 정상. 기본 화면에서 시작 행동이 아래로 밀림; 좁은 PC에서는 메시지 버튼과 겹침 |
| 3 | 사진 분석 설정 펼치기→다시 확인 | 실패 상태 확인. 재시도 뒤에도 조회 오류와 ‘사용 안 함’ 동시 표시 |
| 4 | 운동 직접 찾기→스쿼트 검색 | 검색 반영 정상. 동일 계열 운동의 두 평가 방식 선택 기준이 불명확할 가능성 |

### 추가 발견과 우선순위

**PD-01 · 동의 상태 조회 실패를 ‘사용 안 함’과 동시에 표시 — High / P1 / 직접 관찰.**
03·04에서 운동 종류 자동 인식과 측정 중 사진 관찰 모두 조회 오류인데 ‘사용 안 함’으로 표시한다. 다시 확인을 눌렀을 때 잠시 확인 중으로 바뀐 뒤 같은 상태로 돌아왔다. 조회 실패는 미동의나 철회 확인이 아니므로 ‘확인할 수 없음’으로 분리해야 한다. 사용자가 설정이 꺼졌다고 안심할 수 있다는 영향은 추론이다. 오류의 서버/DB 원인은 이 화면으로 확정하지 않았다. 설정 조회 복구와 실패 상태 표현을 먼저 처리한다.

**PD-02 · 좁은 PC에서 메시지가 카메라 버튼 일부를 덮음 — Medium / P2 / 직접 관찰.**
05의 390×844 화면에서 우하단 메시지 버튼이 카메라 켜기 버튼 오른쪽을 덮는다. 버튼 전체가 작동 불가라고 단정하지는 않는다. 좁은 PC에서도 데스크톱 기능 정책은 유지하되, 떠 있는 메시지와 주요 실행 버튼이 같은 자리를 차지하지 않도록 공간을 확보해야 한다. 실제 모바일 웹앱에서도 같은지 별도로 확인한다.

**PD-03 · 자세 측정의 시작 행동이 첫 화면에서 멀어짐 — Medium / P2 / 배치는 관찰, 발견성 영향은 추론.**
02의 기본 PC 화면에서는 제목·링크·설정 사이 여백과 큰 준비 미리보기 때문에 카메라 실행 버튼이 현재 화면 아래에 있다. 05에서는 버튼이 하단에 겨우 들어오며 메시지와 겹친다. 시작 버튼이 없는 문제가 아니라 정보 순서·높이 배분 문제다. 준비 설명을 짧게 정리하고 촬영 카메라 선택·켜기 행동을 미리보기 가까이 눈에 띄게 둔다.

**PD-04 · 같은 운동을 서로 다른 측정 방식으로 고르게 함 — Medium / P2 / 항목은 관찰, 혼란은 추론.**
07에서 ‘스쿼트 실시간 측정’과 ‘맨몸 스쿼트 · 사진으로 움직임 관찰’이 함께 나타난다. 무전송/AI 전송, 횟수·관절 평가/간헐적 사진 관찰의 차이를 사용자가 선택 전에 이해할 설명은 현재 보이는 영역에 없다. 운동은 먼저 하나로 찾게 하고, 선택한 운동에서 가능한 결과와 분석 방식을 설명하는 흐름을 검토한다. 두 방식의 실제 정확도나 인식 품질을 이번 화면 검토로 평가하지 않았다.

유지할 점: 01의 맞춤 계획·리포트·대화는 목적별로 구분되고 기존 브랜드가 유지된다. 06·07의 직접 운동 검색과 실시간/사진 관찰 표시도 대안 존재를 알려준다. 필요한 수정은 표시를 삭제하는 것이 아니라, 선택에 필요한 차이를 더 쉽게 설명하는 것이다.

접근성 한계: 펼침 상태와 검색 필드의 레이블은 화면 구조에서 확인했지만, 스크린리더·키보드 전체 이동·색 대비 수치·확대 및 실제 터치 영역을 모두 검증한 것은 아니다. 이미지가 선명하다는 이유로 접근성 통과로 표시하지 않는다.

## 10. 우선 수정과 재검증 — 2026-11-21

기존 작업트리에 수정했으며 이번 검수로 커밋·푸시·운영 배포하지 않았다. 최소 연령은 사용자가 재검토를 요청했으므로 19세 또는 14세 제한을 확정·적용하지 않았다. 운동 기능의 접근 기준과 실제 크루 모임·예약·결제 조건을 분리해 결정해야 한다.

### 반영한 변경

- 동의 조회 실패, 미동의, 동의, 철회 중·실패를 분리했다. 실패를 ‘사용 안 함’으로 표시하지 않는다. 철회 중 화면을 나간 뒤 옛 동의가 조회되더라도 분석을 허용하지 않고 원래 요청한 철회를 재시도한다.
- 동의 선택은 계정·분석 목적·고지 버전별로 유지한다. 새로운 녹화 선택은 매 측정에서 따로 확인하며, 녹화와 종료 후 영상 보관은 구분한다. 프로필 설정에서도 사진 분석 상태와 사용 중지를 관리할 수 있다.
- 실제 조회 실패 원인은 미적용 테이블이었다. HEAD/0행 점검은 204를 반환해 존재 검증으로 충분하지 않았다. GET/0행 점검과 실제 앱 조회에서 PGRST205를 재현했고, 사용자가 `20261121_pose_consents.sql` 실행 완료를 알려준 뒤 GET/0행 200 및 실제 계정의 두 목적 상태 조회 정상화를 확인했다. 사용자 동의값을 대신 승인·철회하지 않았다.
- 카메라 선택·켜기를 미리보기 위로 옮기고 준비 화면 높이를 줄였다. 스쿼트·푸시업의 실시간 측정과 사진 관찰은 하나의 운동에서 차이를 읽고 선택한다. 런지는 실제 기준이 달라 제자리/포워드를 분리했다. 선택만으로 카메라는 실행되지 않는다.
- 799px 이하의 좁은 PC 창에서는 메시지를 상단 아이콘으로 배치해 카메라·계획 입력·보내기를 가리지 않도록 했다. 넓은 PC의 우하단 메시지와 PC의 기능 제한은 유지한다.
- Android GPS 시작 전에 화면 잠금 후 지속 수집과 종료 방법을 안내한다. Google 캘린더는 이메일 계정에서 조건을 먼저 설명하고, 지원하지 않는 연결을 실행하지 않는다.
- 코칭 미전송 질문은 계정·탭별로 30분간 복구하며 로그아웃·계정 변경 시 지운다. 가져온 새 질문과 기존 초안이 충돌하면 선택하도록 했고, 이전 계정의 늦은 응답은 현재 초안을 변경하지 않는다. 작업 화면도 계정이 바뀌면 재마운트한다.
- 식단→상품 상세→식단 복귀에서 제안·선택 끼니 또는 저장 날짜·카드 위치를 유지한다. 질문·식단 본문은 URL에 넣지 않는다.
- AI 정보 안내는 코칭 입력과 리포트 생성에서 항상 열 수 있다. 실제 자료 범위와 OpenAI 수신자를 밝히며, 계정 필드 자동 첨부 제외와 자유 입력에 적은 개인정보를 구분한다. 이 안내는 법적 동의 저장·검사 구현을 대체하지 않는다.

### 독립 리뷰 및 자동 검증

디자인/구현/검증 담당을 나누고 서로 다른 파일을 검토했다. 독립 검토에서 발견한 미완료 철회 재허용, 새 추천 질문 소실, 이전 계정의 늦은 초안 갱신, Android 안내 창 뒤로가기, 키보드 중 정보 안내 숨김을 수정하고 재검토했다.

- Node.js 22.19.0, 클라이언트 355/355, 서버 149/149 통과. 서버의 최초 11개 실패는 로컬 소켓 EACCES이며, 로컬 연결을 허용한 재실행에서 통과했다.
- 최종 웹 빌드 통과. Android 동기화·디버그 APK 빌드 통과, 네이티브 단위 테스트 Gradle 작업 성공.
- 테스트·빌드는 실기기 인식, 실제 Google 권한 왕복, 운영 데이터 저장 성공을 의미하지 않는다.

### 제보와 확인한 원인
