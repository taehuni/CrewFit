# 자세 영상 보관

사용자가 선택한 경우에만 마이크 없이 측정 시작 후 최대 120초를 녹화한다. 녹화가 끝나도 자세 측정은 계속된다. 종료 후 요약을 먼저 저장하고 영상을 별도로 전송한다. 영상 업로드 실패가 측정 요약을 취소하지 않는다.

사용자의 최신 요청에 따라 원본 영상은 본인이 직접 삭제할 때까지 보관한다. 보관 만료, 자동 삭제 작업, 정리 스케줄러는 구현하지 않는다. 24시간이 지난 측정에도 영상을 저장하거나 재생할 수 있다.

## 접근과 직접 삭제

모든 요청에서 사용자 JWT/RLS로 본인의 저장된 측정 기록을 확인한다. Storage와 영상 테이블은 일반 사용자의 직접 접근을 금지하며 서버 내부 서비스 권한으로만 업로드·서명·삭제한다. 공개 버킷을 사용하지 않는다.

재생 링크는 180초 동안 유효하다. 이는 링크의 만료이며 원본의 보관 기한이 아니다. 만료된 링크는 새로 요청할 수 있다. 링크를 받은 사람은 유효 시간 동안 접근할 수 있으므로 공유하지 않는다. 이미 내려받거나 버퍼링한 바이트는 회수할 수 없다.

사용자가 삭제하면 새 재생 링크 발급을 차단하고 파일 삭제를 요청한다. 늦은 업로드가 삭제를 취소하지 못하도록 삭제 상태의 메타데이터는 유지한다. 파일 삭제 실패 시 오류를 반환하며 사용자가 삭제를 다시 요청할 수 있다. 자동 재시도 작업은 없다.

계정·측정 기록이 삭제될 때 Storage 객체까지 제거하는 별도 흐름은 아직 구현하지 않았다. 연결이 사라지면 본인 기록 확인을 통과할 수 없어 재생 링크는 발급되지 않지만 원본이 물리적으로 삭제되는 것은 아니다. 계정 삭제 기능을 확장할 때 별도로 연결해야 한다.

## 필요한 설정

2026-11-18 사용자 승인으로 Supabase에서 `20261118_pose_sessions_extended.sql`과 최신 `20261118_pose_videos.sql`을 실행했고 성공을 확인했다. 영상 설정에는 `delete_pending` 상태가 포함되며 `pose-videos` 버킷의 비공개 설정(`public=false`)과 33,554,432바이트 제한을 확인했다. 원본 자동 만료·삭제는 설정하지 않았다. 실제 영상 업로드·재생·삭제는 아직 검증하지 않았다.

다른 환경에는 위 마이그레이션 적용이 필요하다. 전용 비공개 버킷·메타데이터가 없으면 API는 503을 반환한다. 기존 서버 service-role 설정을 사용하며 키를 클라이언트로 전달하지 않는다.

## API

인증 필수 `/api/pose/sessions/:id/video`:

- `PUT`: raw Blob, `Content-Type: video/webm` 또는 `video/mp4`, `X-Video-Duration-Seconds` 0초 초과~120초. 최대 32MiB. `{video:{sessionId,expiresAt:null,durationSeconds,sizeBytes}}` 반환. 동일 파일 재시도는 같은 결과이며 다른 파일 교체는 409.
- `GET`: `{video:null}` 또는 위 메타데이터에 `url` 추가. 업로드 중·삭제된 영상은 null. 명시적으로 요청한 삭제가 실패한 경우 `{video:null,deletionPending:true}`로 삭제 재시도를 안내한다. 조회 요청 자체가 파일을 삭제하지 않는다.
- `DELETE`: 성공 204. 측정 요약은 유지한다.

컨테이너 헤더·크기·MIME·신고된 길이를 검사한다. 서버가 실제 재생 길이를 디코딩 검사하지는 않는다. 120초 제한은 공식 클라이언트에서 강제하며 조작된 길이 헤더는 실제 길이의 증명이 아니다. 동시 업로드 4개·사용자당 1개 제한은 프로세스 단위다. 원본·경로·서명 URL·사용자 식별자를 로그에 남기지 않는다.
