# 2026-11-26 릴리스 검증

## 범위

`render_test`의 `cf05f21` 이후 누적 변경: 부위 그림과 51개 운동 선택, 자세 측정·동의·복구, 코칭 대화·계획 검토와 초안, 홈·식단 완료 표시, 캘린더 연결 확인, 기록·피드·프로필·스토어 UI 개선. 사용자 요청으로 기존 Render CrewFit 서비스에 배포한다. iOS 설치형 앱 배포는 포함하지 않는다.

운동 선택의 51개 항목이 모두 실시간 횟수 측정을 지원하는 것은 아니다. 실시간 관절 평가 3개, 사진 관찰 47개, 이름·시간 기록 1개로 구분하며 카메라 정확도는 별도 검증 대상이다.

## 검증 결과

- Node.js 22.19.0.
- 클라이언트 자동 테스트: 399/399 통과.
- 서버 자동 테스트: 156/156 통과. 첫 실행의 로컬 연결 권한 오류는 실행 권한을 조정한 재실행에서 해소했다.
- 웹 빌드, Android 동기화 및 APK 빌드 통과. 빌드 전후 소스 443개 변경 없음, Android 자산 153개와 APK 내부 파일의 SHA-256 일치 확인.
- 독립 검토: 클라이언트, 서버, 공개 산출물·개인정보 범위를 각각 검토했다. 신규 P0/P1 발견 없음은 검토 범위에 한정하며, 실기기 정상 동작 보장이 아니다.
- 수정한 회귀: 제안 저장 후 최근 대화로 복귀했을 때 저장 수가 이전 캐시에 남던 문제. 사용자별 코칭 캐시 무효화와 실제 QueryObserver 회귀 테스트로 재검증했다. 타 계정 캐시를 변경하지 않는다.
- 캘린더 연결 확인은 계정/읽기 접근 확인이며 일정 쓰기 성공을 보장하지 않는 것으로 문구와 주석을 바로잡았다. CrewFit 복구 캐시의 탭 범위와 Supabase SDK 자체 세션 보관을 구분했다.
- 비밀 검사: 검토한 변경 텍스트에서 API 키·JWT·DB 비밀번호 패턴 검출 없음. `.env`, APK, 로컬 로그와 과거 Render 관리 화면 `deploy-proof.png`는 커밋에서 제외했다.

| iOS 설치형 앱 | **미지원**. iPhone 웹/PWA와 별개다. |

## 실제 기기에서 남은 필수 확인

1. 운동 선택 → 카메라 허용 → 미리보기 → 동작/횟수 또는 사진 관찰 피드백 → 종료 → 결과·영상 저장 → 재조회. 각 단계를 따로 확인한다.
2. 카메라 거절/취소, 전후면 전환, 화면 숨김 후 복귀, 종료 뒤 재시작. 늦은 요청이 카메라를 다시 켜지 않아야 한다.
3. 계획 입력·편집에서 날짜/시간, 긴 제목, 키보드와 회전 중 버튼 접근. 코칭 대화와 제안 목록의 독립 스크롤.
4. Google 연결·동의 → 원래 화면 복귀 → 일정 전송 → 대상 캘린더에서 실제 확인. iPhone Safari/PWA 및 Android 외부 브라우저 경로를 구분한다.

동의 저장 마이그레이션은 사용자가 적용했고 이전 조회 확인 이력이 있다. 이번 배포에서 자동 재실행하지 않는다. 영상 자동 삭제는 도입하지 않는다. 실제 사용자에게 메시지를 보내거나 건강·위치·캘린더 데이터를 수정하는 운영 테스트는 수행하지 않는다.
