# CrewFit 개발 계획서

> 2인 캡스톤 · 15주 · 웹 기반 AI 코칭 러닝 크루 플랫폼
> 상세 기획/제약은 [`../CLAUDE.md`](../CLAUDE.md) 참조.

## 1. 팀 구성 / 역할

| 이름 | 역할 |
|---|---|
| 민태훈 | PM, 백엔드(API·DB·AI 연동·크루 매칭), DB 설계 |
| 김민규 | 요구사항 분석, UI/UX 디자인, 프론트엔드(GPS 트래킹 UI 포함) |

## 2. 기술 스택

- **Frontend**: React (Vite) — 모바일 퍼스트 반응형
- **Backend**: Node.js + Express — API, AI 코칭, 크루 매칭
- **DB / 인증**: Supabase (PostgreSQL + Auth) — 클라우드 관리형, RLS로 데이터 보호
- **AI**: LLM API (기록 기반 코칭 피드백)
- **지도/GPS**: 카카오맵 JS SDK + 브라우저 Geolocation/Wake Lock API

## 4. 구현 단계 상세 (6~10주차)

| 순서 | 기간 | 백엔드(태훈) | 프론트(민규) | 완료(Done) 기준 |
|---|---|---|---|---|
| ① 인증 | 0.5주 | `profiles` 적용, `/api/me` 토큰 검증 | 가입/로그인 폼, 세션 유지, 보호 라우트 | 가입→로그인→새로고침에도 세션 유지 |
| ② 기록+AI | 1.5주 | `workouts` CRUD, AI 코칭 API(서버측 키) | 기록 입력/목록/상세, 피드백 표시 | 기록 저장→목록→AI 피드백 생성 |
| ③ 크루매칭 | 1주 | `crews`/`crew_members`, 규칙기반 매칭 | 크루 탐색/생성/가입 UI | 조건 추천 목록→가입 |
| ④ 피드+GPS | 2주 | `posts`/`likes`/`comments` API | GPS 트래킹(다크 UI)+카카오맵 폴리라인, 피드 | 러닝→경로 표시, 피드 상호작용 |

## 5. 리스크 관리

| 리스크 | 대응 |
|---|---|
| GPS 야외 테스트는 실기기·실제 러닝 필요 | 구현 ④ 시작 시점부터 짬짬이 실기기 테스트, 마지막에 몰지 않기 |
| AI 코칭 프롬프트 튜닝에 실데이터 다수 케이스 필요 | 기록 기능 완성 후 여유 두고 반복 튜닝 |
| Supabase 새 테이블마다 RLS 누락 위험 | 테이블 생성 시 RLS+정책을 한 세트로 처리 |
| 웹 GPS 백그라운드 끊김(구조적 한계) | 버그 아님을 UI로 안내, Wake Lock으로 완화 |

## 6. 향후 확장 기능 (Post-MVP)

MVP 7개 기능 완료 후 일정 여유가 있을 때만 착수. 범위 관리를 위해 MVP와 분리.

| 기능 | 요지 | 착수 조건 |
|---|---|---|
| 코스 추천 (EXT-01) | 저장된 러닝 경로 기반 규칙 추천(출발점 근처+거리대→인기순) | 구현 ④(GPS) 이후 경로 데이터 누적 시 |

> 상세 설계는 [`요구사항분석.md`](요구사항분석.md#8-향후-확장-기능-post-mvp-후보) 참조. FR-03 경로 데이터를 재활용하므로 추가 수집·PostGIS 없이 컬럼 2~3개로 구현 가능.
