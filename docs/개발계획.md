|---|---|---|

## 2. 기술 스택

- **Frontend**: React (Vite) — 모바일 퍼스트 반응형. TanStack Query + react-router
- **Backend**: Node.js + Express — AI 코칭, 크루 매칭·승인, 집계 API. 기본은 사용자 토큰으로 Supabase 접근(RLS 적용)
- **DB / 인증 / 파일**: Supabase (PostgreSQL + Auth + Storage) — 클라우드 관리형, 기본 권한선은 RLS (admin 예외 2곳은 서버 코드가 권한선)
- **AI**: LLM API (기록·식단·목표 종합 코칭 피드백)
- **지도/GPS**: 카카오맵 JS SDK + 브라우저 Geolocation/Wake Lock API

## 4. 구현 단계 상세 (6~11주차)

| 순서 | 기간 | 백엔드(태훈) | 프론트(민규, ①은 태훈 선행) | 완료(Done) 기준 |
|---|---|---|---|---|
| ⓪ 스키마 | 첫날 | `schema.sql` + `seed_regions.sql` 적용, `supabase.js` 분리(D-15), `requireAuth`에 RLS 클라이언트 부착 | — | SQL Editor에서 통째로 무오류 실행, `/api/me` 동작 |
| ① 인증 | 0.5주 | `/api/me` | 태훈: 뼈대(react-router·TanStack Query·AuthContext·보호 라우트) + 디자인 시스템(토큰·레이아웃·기본 컴포넌트) + 로그인 화면 1개 완성본 / 민규: 가입·비밀번호 재설정, AuthContext, 보호 라우트, Query·Router 세팅 | 가입→로그인→새로고침 유지→재설정 메일 |
| ② 기록·식단·목표·AI | 1.5주 | `/api/feedback/generate`, `/api/dashboard`, `/api/exercises/merge`, 프롬프트 튜닝 | 종목별 입력 폼(헬스 세트·자동완성), 식단, 목표, 대시보드, 피드백 화면 | 헬스+러닝 기록→주간 피드백 생성→대시보드 달성률 |
| ③ 크루 | 1.5주 | `/api/crews/match`·`join`·`approve`·`reject`·`stats` | 탐색·매칭·생성·상세·멤버 관리·통계 카드 | 승인제 크루 신청→리더 승인→can_post 부여 |
| ④ 피드·GPS·프로필 | 2주 | (클라 직접이 대부분) 사진 정책 검증 | 전체/크루 피드·글쓰기·사진·좋아요·댓글, GPS 트래킹+카카오맵, 회원 페이지·설정 | 러닝→경로→글에 첨부(include_route)→크루원만 경로 보임 |

- ⓪은 문서 SQL을 실제로 돌려보는 첫 검증 — 순서·문법 오류는 여기서 전부 잡음.
- 서버 API는 9개(`architecture/api.md`, `/health` 제외). 나머지 CRUD는 클라가 supabase-js로 직접, RLS가 막음.

진행 상태와 다음 행동은 [설계 결정 기록의 진행 상황](architecture/decisions.md#진행-상황-설계-이후-최신이-위)에서 관리한다.

## 5. 리스크 관리

| 리스크 | 대응 |
|---|---|
| GPS 야외 테스트는 실기기·실제 러닝 필요 | 구현 ④ 시작 시점부터 짬짬이 실기기 테스트, 마지막에 몰지 않기 |
| AI 코칭 프롬프트 튜닝에 실데이터 다수 케이스 필요 | 기록 기능 완성 후 여유 두고 반복 튜닝 |
| LLM 호출 비용 | 입력 해시 같으면 재호출 없음, 재생성 3회/기간, 5회/분·20회/일 상한 (D-06) |
| Supabase 새 테이블마다 RLS 누락 위험 | 스키마는 `schema.sql` 한 파일로 관리, 테이블·정책·컬럼 권한을 한 세트로 |
| 웹 GPS 백그라운드 끊김(구조적 한계) | 버그 아님을 UI로 안내, Wake Lock으로 완화 |

## 6. 향후 확장 기능 (Post-MVP)

MVP 10개 기능 완료 후 일정 여유가 있을 때만 착수. 범위 관리를 위해 MVP와 분리.

| 기능 | 요지 | 착수 조건 |
|---|---|---|
| 코스 추천 (EXT-01) | 저장된 야외 경로 기반 규칙 추천(출발점 근처+거리대→인기순) | 구현 ④(GPS) 이후 경로 데이터 누적 시 |
| 카카오 로그인 (EXT-02) | Supabase Auth 소셜 프로바이더 | 이메일 인증 안정화 후 |
| 리더 양도 (EXT-03) | `crews.owner_id` 변경 | 크루 기능 안정화 후 |

> 상세는 [`요구사항분석.md`](요구사항분석.md#8-향후-확장-기능-post-mvp-후보) 8절 참조.
