# CrewFit 사용자 흐름·UI 점검 — 2026-11-24

## 범위와 증거

PC 웹, 모바일 웹/PWA, Android 설치형 앱의 주요 흐름을 대상으로 한다. 운동을 처음 시작하는 회원도 설명을 읽거나 기술 설정을 고르지 않고 다음 행동을 알 수 있는지를 기준으로 삼았다. 기존 로고·색상·둥근 카드와 기기별 기능 구분을 유지한다.

- 기준 소스: `render_test`, 기존 미커밋 변경을 포함한 작업 트리. 이번 작업 이전 변경은 보존한다.
- 역할: 메인 구현·화면 점검, 별도 사용자 흐름·코드·최종 화면 검토, Claude Opus CLI의 익명 시나리오 자문, 모의 환경·플랫폼 준비. Opus는 실제 소스·화면 검토와 구분한다.
- 증거 유형: **코드 확인**은 구현 근거, **화면 확인**은 실제 브라우저/앱 조작, **추론**은 아직 재현하지 못한 사용자 영향이다. 서로 대체하지 않는다.
- 모의 인증/API로 만든 화면 검증은 실제 서버 저장·OAuth·인식 검증과 구분한다. 실제 회원의 건강·위치·영상·메시지 데이터를 새로 쓰거나 문서에 복사하지 않는다.

## 남은 서비스 항목

- 식단 제안은 그대로 저장할 수 있지만 날짜·끼니·음식을 계획 단계에서 수정하는 기능은 없다. 실제 먹은 기록 편집과 별개인 개선 과제다.
- 가입 약관·운영자 정보·최소 연령, 계정 탈퇴·데이터 내보내기, 인바디 실제 API 연결은 UI 정리만으로 완료되는 범위가 아니다. 확정되지 않은 정책이나 연동을 구현됐다고 표시하지 않는다.
- 실제 카메라 미리보기, 운동 종류 판별, 평가 피드백, 결과 저장, 영상 저장은 각각 별도 검증 대상이다. 모의 화면 성공으로 실기기 인식 성공을 주장하지 않는다.

## 유지하는 것

사용자가 실제로 선택해야 하는 사진 분석 사용과 선택적 영상 보관, GPS 경로 공개, 삭제 확인은 유지한다. 숨겨진 개인정보 전송을 만들지 않는다. 일반 사용자가 고를 필요 없는 측정 튜닝과 장식 설명은 제거 대상으로 삼는다.

## 수정 결과

- FLOW-01: 수동 기록의 저장 ID를 반환하고 해당 상세 화면으로 이동한다. 저장 안내와 기존 기록 목록 필터를 유지하며, 뒤로가기로 작성 폼에 돌아가 중복 저장하는 상황을 줄였다.
- FEED-01: 본인 기록과 실제 경로 존재 여부를 확인한다. 좌표 전체를 불러오지 않는다. 경로 없는 기록의 공유 체크는 숨긴다. 기존 경로 공유 글을 수정할 때는 선택을 보존하며, 확인 실패는 재시도 또는 공유 제외를 명시적으로 선택해야 한다.
- FEED-02: 삭제 확인을 선택한 댓글 아래로 옮겼다. 취소에 초기 포커스, 취소/Escape 시 원래 버튼 복귀, 삭제 후 인접 댓글 포커스를 제공한다.
- FEED-03: 크루 상세에서도 작성 권한이 없을 때만 짧게 이유를 표시한다.
- COACH-01/02: 반복된 영문 제목·설명·제목을 줄였다. 모두 저장한 제안은 완료 상태와 해당 제안의 날짜로 이동하는 ‘내 계획 보기’를 제공한다. 일정 선택과 위치·캘린더 공유 구분은 유지한다.
- PROFILE-01/02, COPY-01: 설정의 큰 프로필 소개 카드·번호·반복 설명을 제거했다. 프로필 편집의 이미지 선택은 유지한다. 오류 재시도를 추가하고 가입 전 계정 병합 설명을 없앴다.
- 메시지: PC는 Enter 전송/Shift+Enter 줄바꿈, 모바일은 Enter 줄바꿈으로 구분했다. 화면 폭이 아니라 기존 기기 판별을 사용한다. 한글 조합 중 Enter는 전송하지 않는다.
- 인증: 미분류 영문 오류를 사용자가 할 수 있는 행동이 담긴 한국어 안내로 바꿨다. 기존 한국어 업무 안내는 유지한다.
- 캘린더: 연결 전에는 연결, 연결 완료 시에는 저장한 계획에서 일정 추가가 주요 행동이다. 재연결은 보조 행동이며 Google 계정 불일치와 Safari/PWA 연결 차이에 관한 안내는 유지한다.

## Claude Opus 참여 범위

Claude Code 2.1.323 CLI를 사용했고, 성공한 자문의 응답 모델은 `claude-opus-5-5`였다. **제품명·소스·사용자 데이터 없는 가상 운동서비스 상황 6개에 대한 UX 자문**을 받았다. 기록 저장 결과 확인, 오류 재시도, 모바일 Enter 입력, 반복 동의와 설명의 축소, 실제 플랫폼 구분을 검토했다. 실제 CrewFit 화면이나 코드를 Opus가 검수한 것은 아니다.

원본 소스 전송 요청은 자동 승인 검토에서 파일·외부 목적지에 대한 명시 승인 부족으로 거부됐다. 그 전송은 중단했고, 코드와 개인정보가 없는 별도 자문으로 범위를 줄였다. 제품 코드의 구체적인 결함은 내부 독립 검토와 메인 확인을 통해 판단했다.

## 검수 재개: Android 이탈 확인 창 뒤로가기

- 재현: 저장하지 않은 편집에서 Android 시스템 뒤로가기 → 이탈 확인 창 → 시스템 뒤로가기 재입력. 기대는 확인 취소·편집 복귀다. 수정 전에는 확인 창이 Back을 소비하지 않아 `navigate(-1)`가 다시 실행되고 확인 상태가 유지됐다. 현재 React Router와 `consumeSurfaceBack`을 이용한 메모리 재현으로 이 동작을 확인했으며, 데이터가 즉시 사라지는 문제로 판단하지 않았다.
- 수정: `useLeaveGuard.jsx`가 `leaveGuardBack.js`를 통해 확인 창이 열린 동안 capture 단계로 Back을 먼저 받아 `preventDefault`, `stopImmediatePropagation`, `blocker.reset()`을 실행한다. 다른 열린 메시지 창의 일반 Back 리스너와 경로 이동이 함께 실행되지 않으며, 확인 창 종료 시 리스너를 해제한다. 기존 제안 검토 상태 보호 변경은 보존했다.
- 검증: Node 22.19.0에서 관련 테스트 13개 통과(신규 2개 포함), 최종 전체 381개 통과. 새 테스트는 실제 React Router에서 중복 POP 없이 확인 취소·원래 방문 이력 보존을 검증하고, DOM 이벤트 단계 모형으로 먼저 열린 창보다 우선 처리·해제 후 기존 창 처리 복귀를 검증한다. 독립 코드 검토 완료, PC Escape 취소·입력 유지·포커스 복귀 확인. Android 16:00 설치 앱에서 시스템 Back→확인창→Back→확인창만 닫힘·선택 유지까지 직접 확인했다.
