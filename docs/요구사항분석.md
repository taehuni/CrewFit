# CrewFit 요구사항 분석서

> 2~3주차 산출물 · MVP 범위 기준. 설계(4~5주차)에서 확정된 내용을 반영해 갱신 — 결정 근거는 [`architecture/decisions.md`](architecture/decisions.md), 기획 원본은 [`../CLAUDE.md`](../CLAUDE.md).

## 1. 프로젝트 개요

혼자 하면 동기부여가 약하고, 워치·네이티브 앱 없이도 운동을 기록·공유하고 싶은 사람을 위한 **웹 기반 운동 크루 플랫폼**. 브라우저만으로 다종목 운동 기록(헬스 세트, 야외 GPS 트래킹) + 식단·목표 + AI 코칭 + 크루 소셜 기능을 제공한다.

## 2. 타겟 사용자

| 페르소나 | 특징 | 핵심 니즈 |
|---|---|---|
| 입문 운동러 | 러닝·헬스 시작한 지 얼마 안 됨, 워치 없음 | 폰만으로 기록, 뭘 개선할지 코칭 |
| 소셜 운동러 | 같이 할 사람/자극 원함 | 동네·종목·요일 맞는 크루, 피드로 서로 인증 |
| 기록 관리형 | 꾸준함·성장 추적 중시 | 목표·스트릭·통계 대시보드 |

## 3. 사용자 시나리오 (핵심 흐름)

1. **가입/로그인** → 이메일로 가입, 닉네임 설정. 비밀번호 잊으면 재설정 메일
2. **기록** → 헬스: 운동명(자동완성)·세트·횟수·무게 입력 / 야외(러닝·걷기·자전거): "트래킹 시작" → 다크 화면(거리·시간 크게) → 종료 → 경로가 지도에 표시되고 기록 저장. 수영·기타는 시간(+거리) 입력
3. **식단·목표** → 오늘 먹은 것 기록, "이번 주 러닝 3회" 같은 목표 설정
4. **코칭** → "이번 주 피드백" → 기록·식단·목표를 종합한 AI 조언. 같은 입력이면 즉시 재표시, "다시 생성"은 기간당 3회
5. **크루** → 종목·지역·요일·레벨로 크루 매칭 → 즉시 가입 또는 신청(승인제) → 리더가 승인·글쓰기 권한 부여. 또는 직접 생성(리더)
6. **소셜** → 전체 피드/크루 피드에 기록(경로 포함 가능)·사진 1장과 함께 게시 → 좋아요/댓글. 리더는 공지 고정
7. **대시보드·프로필** → 통계·스트릭·목표 달성률 확인. 기록 공개 범위(전체/크루/나만)와 크루 소속 노출 설정. 남의 회원 페이지 열람

## 4. 기능 요구사항 (FR)

| ID | 기능 | 설명 | 우선순위 |
|---|---|---|---|
| FR-01 | 회원가입/로그인 | Supabase Auth 이메일 인증, 닉네임 프로필, 비밀번호 재설정 | 필수 |
| FR-02 | 운동 기록 CRUD | 6종목(러닝·걷기·자전거·수영·헬스·기타). 공통: 종목·날짜·소요시간 필수, 메모 선택. 헬스: 세트(운동명·세트번호·횟수·무게), 운동명 자동완성·이름 합치기. 야외 3종목: 거리·GPS 경로 | 필수 |
| FR-03 | 실시간 GPS 트래킹 | 러닝·걷기·자전거만. 브라우저 위치로 추적, 종료 후 경로를 카카오맵에 표시하고 기록+경로 저장 | 필수 |
| FR-04 | AI 코칭 피드백 | 일/주/월 단위, 기록·식단·목표 종합. 기간당 1개, 입력이 같으면 재호출 없음, 재생성 3회/기간, 호출 상한 5회/분·20회/일 | 필수 |
| FR-05 | 크루 | 종목·지역(고정 목록)·요일·레벨 규칙 매칭. 생성(리더), 즉시가입/승인제, 리더가 승인·거절·강퇴·글쓰기 권한(`can_post`) 관리. 크루 합계 통계(기여 3명 미만 비표시) | 필수 |
| FR-06 | 피드 | 전체 피드 + 크루 피드. 글 종류(기록/모집/자유), 기록·경로 첨부, 사진 1장, 좋아요(명단 공개)/댓글. 수정은 작성자만, 리더는 크루 글 삭제·자기 글 고정 | 필수 |
| FR-07 | 대시보드 | 누적 통계, 스트릭(하루 1건, KST), 목표 달성률 | 필수 |
| FR-08 | 식단 기록 | 날짜·끼니·음식 목록·메모. 본인만 열람, 칼로리 DB 없음 | 필수 |
| FR-09 | 목표 | 횟수/거리/시간 × 종목(또는 전체) × 주/월, 개수 제한 없음 | 필수 |
| FR-10 | 프로필·회원 페이지 | 공개 카드(닉네임·주종목·레벨) + 비공개 설정(지역·요일·목표 메모). 기록 공개 범위 3단계(기본 크루), 크루 소속 노출 토글. 회원 페이지 `/users/:id` | 필수 |

## 5. 비기능 요구사항 (NFR)

| ID | 항목 | 요구사항 |
|---|---|---|
| NFR-01 | 반응형 | 모바일(운동 중)·데스크톱(피드 열람) 둘 다 대응, 모바일 퍼스트 |
| NFR-02 | 보안 | 기본 권한선은 Supabase RLS. 서버도 사용자 토큰으로 접근, service_role은 크루 집계·AI 피드백 저장 2곳만이며 거기서는 서버 코드가 권한선. 식별 컬럼 불변, GPS 경로는 글에 첨부했을 때만 노출 |
| NFR-03 | 성능 | 트래킹 중 지도 실시간 렌더링 안 함(종료 후만), CPU/발열 최소화 |
| NFR-04 | 호환성 | 최신 Chrome/Safari. GPS·Wake Lock은 HTTPS 필수 |
| NFR-05 | 전력 | 트래킹 시 다크 미니멀 UI로 OLED 전력 절감 |
| NFR-06 | 비용 | LLM 호출은 입력 해시 캐시 + 사용자별 상한으로 제한 |

## 6. 화면 목록

| 화면 | 주요 요소 |
|---|---|
| 로그인/회원가입/비밀번호 재설정 | 이메일·비밀번호·닉네임 입력, 재설정 메일 |
| 홈/대시보드 | 통계 카드, 스트릭, 목표 달성률, "트래킹 시작"·"기록 추가" 버튼 |
| 기록 입력 (종목별) | 종목 선택 → 헬스: 세트 표(운동명 자동완성) / 야외: 거리·시간 / 수영·기타: 시간(+거리), 메모 |
| 기록 목록/상세 | 리스트, 상세(세트·경로), 수정·삭제 |
| GPS 트래킹 | (다크) 거리·시간·페이스 크게 표시, 정지 버튼 |
| 트래킹 결과 | 카카오맵 경로 폴리라인, 기록 요약, 저장 |
| 식단 | 날짜별 끼니 목록, 입력 |
| 목표 | 목표 목록·추가·활성/비활성 |
| AI 피드백 | 일/주/월 선택, 피드백 본문, "다시 생성"(남은 횟수) |
| 크루 탐색/매칭 | 조건 필터(종목·지역·요일·레벨), 크루 카드(인원수), 가입/신청 |
| 크루 생성 | 이름·소개·종목·레벨·지역(드롭다운)·활동 요일·가입 방식 |
| 크루 상세 | 소개, 멤버 목록, 크루 통계, 크루 피드. 리더: 신청 승인/거절, 권한·강퇴, 크루 수정·삭제 |
| 전체 피드/크루 피드 | 글 목록(종류 필터), 고정글, 좋아요/댓글 |
| 글쓰기 | 종류·공개 범위·크루 태그·기록 첨부(경로 포함 여부)·사진 1장·본문 |
| 프로필 편집/설정 | 닉네임·주종목·레벨, 지역·요일·목표 메모, 기록 공개 범위, 크루 소속 노출, 로그아웃 |
| 회원 페이지 `/users/:id` | 닉네임·주종목·크루 목록·기록 요약 (공개 범위에 따름) |

## 7. 제약사항 (웹 플랫폼 한계 — 반드시 UI 안내)

| 제약 | 내용 | 대응 |
|---|---|---|
| GPS 백그라운드 | 화면 끄거나 앱 전환 시 트래킹 끊김(웹 구조적 한계, 버그 아님) | Wake Lock으로 완화 + UI 안내 |
| Web Bluetooth | 심박 등 BLE 센서는 안드로이드 Chrome 한정, iOS Safari 미지원 | 플랫폼별 안내, MVP 제외 |
| 실내/트레드밀 | GPS 특성상 지원 불가 | 헬스·기타 종목으로 수동 기록 |
| 화면 밝기 | 웹 표준 밝기 조절 API 없음 | 다크 미니멀 UI로 대체 |
| 사진 표시 | 비공개 버킷이라 `<img>`에 인증 헤더를 못 실음 | 서명 URL(`createSignedUrls`) 발급 |

## 8. 향후 확장 기능 (Post-MVP 후보)

MVP 완료 후 여유 시 추가. **MVP 범위 아님** — 일정 리스크 방지를 위해 분리 관리.

| ID | 기능 | 설명 | 전제 |
|---|---|---|---|
| EXT-01 | 코스 추천 | 저장된 야외 경로 기반, 출발점 근처+목표 거리대 필터 → 인기(많이 뛴)순 추천 | FR-03 경로 데이터 누적 후 가능 |
| EXT-02 | 카카오 로그인 | Supabase Auth 소셜 프로바이더 추가 | 이메일 인증 안정화 후 (D-12) |
| EXT-03 | 리더 양도 | `crews.owner_id` 변경 + 멤버 행 조정 | 현재 owner_id 불변 (D-17) |
| EXT-04 | 고아 사진 정리 | 글 저장 전 업로드만 하고 버린 storage 객체 삭제 배치 | — (D-26) |

**코스 추천 설계 방향 (규칙 기반 — 임베딩/추천 알고리즘 아님):**
- **재활용**: FR-03에서 저장하는 `activity_routes.points` 그대로 사용, 새 데이터 수집 없음
- **로직**: `출발점 근처(위경도 bounding box) + 목표 거리대 필터 → 많이 뛴 순 정렬`
- **DB**: 경로에 `start_lat`/`start_lng` 컬럼만 추가하면 됨 (거리는 `activities.distance_m`, PostGIS 불필요)
- **UI**: 카카오맵에 후보 경로 미리보기
- **주의**: 경로는 글에 `include_route`로 첨부된 것만 공개 대상 (D-23)

## 9. 제외 범위

- iOS/Android 네이티브 앱
- 워치 자동 실시간 연동(HealthKit/Health Connect — 네이티브 전용)
- 결제, 다국어, 실시간 화상/음성
