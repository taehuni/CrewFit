# CrewFit 요구사항 분석서

> 2~3주차 산출물 · MVP 범위 기준. 기획 원본은 [`../CLAUDE.md`](../CLAUDE.md).

## 1. 프로젝트 개요

혼자 뛰면 동기부여가 약하고, 워치·네이티브 앱 없이도 러닝을 기록·공유하고 싶은 러너를 위한 **웹 기반 러닝 크루 플랫폼**. 브라우저만으로 실시간 GPS 트래킹 + AI 코칭 + 크루 소셜 기능을 제공한다.

## 2. 타겟 사용자

| 페르소나 | 특징 | 핵심 니즈 |
|---|---|---|
| 입문 러너 | 러닝 시작한 지 얼마 안 됨, 워치 없음 | 폰만으로 기록, 뭘 개선할지 코칭 |
| 소셜 러너 | 같이 뛸 사람/자극 원함 | 크루 참여, 피드로 서로 인증 |
| 기록 관리형 | 꾸준함·성장 추적 중시 | 통계·스트릭 대시보드 |

## 3. 사용자 시나리오 (핵심 흐름)

1. **가입/로그인** → 이메일로 가입, 닉네임 설정
2. **러닝** → "러닝 시작" → 다크 트래킹 화면(거리·시간 크게) → 종료 → 경로가 지도에 표시되고 기록 저장
3. **코칭** → 저장된 기록 상세에서 "AI 피드백" → 페이스·거리 기반 조언 확인
4. **크루** → 지역·페이스·요일 조건으로 크루 탐색 → 가입, 또는 직접 생성
5. **소셜** → 크루 피드에 러닝 인증 게시 → 좋아요/댓글
6. **대시보드** → 마이페이지에서 누적 거리·스트릭 등 통계 확인

## 4. 기능 요구사항 (FR)

| ID | 기능 | 설명 | 우선순위 |
|---|---|---|---|
| FR-01 | 회원가입/로그인 | Supabase Auth 이메일 인증, 닉네임 프로필 | 필수 |
| FR-02 | 운동 기록 CRUD | 거리·시간·종류 기록 생성/조회/수정/삭제 | 필수 |
| FR-03 | 실시간 GPS 트래킹 | 브라우저 위치로 러닝 추적, 종료 후 경로 지도 표시 | 필수 |
| FR-04 | AI 코칭 피드백 | 기록 데이터 기반 피드백 문구 생성 | 필수 |
| FR-05 | 크루 생성/가입 | 규칙 기반 매칭(지역·페이스·요일 필터) | 필수 |
| FR-06 | 크루 피드 | 게시/좋아요/댓글 | 필수 |
| FR-07 | 마이페이지 대시보드 | 누적 통계, 스트릭 | 필수 |

## 5. 비기능 요구사항 (NFR)

| ID | 항목 | 요구사항 |
|---|---|---|
| NFR-01 | 반응형 | 모바일(러닝 중)·데스크톱(피드 열람) 둘 다 대응, 모바일 퍼스트 |
| NFR-02 | 보안 | Supabase RLS로 타인 데이터 접근 차단, service_role 키는 서버 전용 |
| NFR-03 | 성능 | 트래킹 중 지도 실시간 렌더링 안 함(종료 후만), CPU/발열 최소화 |
| NFR-04 | 호환성 | 최신 Chrome/Safari. GPS·Wake Lock은 HTTPS 필수 |
| NFR-05 | 전력 | 트래킹 시 다크 미니멀 UI로 OLED 전력 절감 |

## 6. 화면 목록

| 화면 | 주요 요소 |
|---|---|
| 로그인/회원가입 | 이메일·비밀번호·닉네임 입력 |
| 홈/대시보드 | 통계 카드, 스트릭, "러닝 시작" 버튼 |
| 러닝 트래킹 | (다크) 거리·시간·페이스 크게 표시, 정지 버튼 |
| 러닝 결과 | 카카오맵 경로 폴리라인, 기록 요약, AI 피드백 |
| 기록 목록/상세 | 기록 리스트, 상세 + 피드백 |
| 크루 탐색/상세 | 조건 필터, 크루 카드, 가입 |
| 크루 피드 | 게시글, 좋아요/댓글 |
| 마이페이지 | 프로필, 통계, 로그아웃 |

## 7. 제약사항 (웹 플랫폼 한계 — 반드시 UI 안내)

| 제약 | 내용 | 대응 |
|---|---|---|
| GPS 백그라운드 | 화면 끄거나 앱 전환 시 트래킹 끊김(웹 구조적 한계, 버그 아님) | Wake Lock으로 완화 + UI 안내 |
| Web Bluetooth | 심박 등 BLE 센서는 안드로이드 Chrome 한정, iOS Safari 미지원 | 플랫폼별 안내, MVP 제외 검토 |
| 실내/트레드밀 | GPS 특성상 지원 불가 | 기능 안내에 명시 |
| 화면 밝기 | 웹 표준 밝기 조절 API 없음 | 다크 미니멀 UI로 대체 |

## 8. 향후 확장 기능 (Post-MVP 후보)

MVP 완료 후 여유 시 추가. **MVP 범위 아님** — 일정 리스크 방지를 위해 분리 관리.

| ID | 기능 | 설명 | 전제 |
|---|---|---|---|
| EXT-01 | 코스 추천 | 저장된 러닝 경로 기반, 출발점 근처+목표 거리대 필터 → 인기(많이 뛴)순 추천 | FR-03 경로 데이터 누적 후 가능 |

**코스 추천 설계 방향 (규칙 기반 — 임베딩/추천 알고리즘 아님):**
- **재활용**: FR-03에서 저장하는 러닝 경로(카카오맵 폴리라인) 그대로 사용, 새 데이터 수집 없음
- **로직**: `출발점 근처(위경도 bounding box) + 목표 거리대 필터 → 많이 뛴 순 정렬`
- **DB**: 경로에 `start_lat`/`start_lng` + `distance` 컬럼만 추가하면 됨 (PostGIS 불필요, bounding box 범위 쿼리로 충분)
- **UI**: 카카오맵에 후보 경로 미리보기
- **예시**: "내 동네에서 5km 뛸 만한 코스, 크루원들이 자주 뛴 순으로"

## 9. 제외 범위

- iOS/Android 네이티브 앱
- 워치 자동 실시간 연동(HealthKit/Health Connect — 네이티브 전용)
- 결제, 다국어, 실시간 화상/음성
